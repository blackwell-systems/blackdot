### H-1: `checkTerminal()` — Dead Unexported Function

**Severity:** High
**Check:** `dead_symbol`
**File:** `/Users/dayna.blackwell/workspace/blackdot/internal/cli/style.go:221`
**Tool:** Grep search across all `*.go` files
**Confidence:** High [LSP Tier 1A: 0 non-test callers found; Grep confirms single definition, zero call sites]

`checkTerminal()` is defined at the bottom of `style.go` but never called anywhere in the codebase.

```go
// style.go:221
func checkTerminal() bool {
    fileInfo, _ := os.Stdout.Stat()
    return (fileInfo.Mode() & os.ModeCharDevice) != 0
}
```

Grep for `checkTerminal()` returns only the declaration line. No caller exists. The function also silently discards the error from `os.Stdout.Stat()` using `_`. This is dead code with an embedded error-ignore pattern.

**Impact:** Unreachable dead code with silent `os.Stat` failure. If terminal detection was intended to control color output, that path was never wired in.

### H-2: `updateSyncTimestamps` and `saveDriftState` — Silent Write Failures

**Severity:** High
**Check:** `silent_failure`
**File:** `/Users/dayna.blackwell/workspace/blackdot/internal/cli/sync.go:588`, `sync.go:634`
**Tool:** Grep + Read
**Confidence:** High [Grep confirms both `os.WriteFile` calls are unguarded]

Two file-write operations in `sync.go` silently drop errors:

**Location 1 — `updateSyncTimestamps` (line 588):**
```go
os.WriteFile(configFile, updatedData, 0644)
// return value discarded; caller never informed of failure
```

**Location 2 — `saveDriftState` (line 634):**
```go
os.WriteFile(driftStateFile, data, 0644)
// return value discarded; next sync will silently use stale baseline
```

Both functions are called from `runSync` (lines 276, 279) after a successful push/pull. If the config write fails, timestamps are not persisted and the user sees no feedback. If the drift state write fails, the next sync has no baseline and will produce spurious CONFLICT results.

The `updateSyncTimestamps` function also hardcodes the config path (`filepath.Join(home, ".config/blackdot/config.json")`) instead of using `config.DefaultManager()`, duplicating the path resolution logic.

**Impact:** Silent data loss; stale drift state causes false conflict escalations on subsequent syncs.

### M-2: `init()` Side Effect in `internal/cli/config.go`

**Severity:** Medium
**Check:** `init_side_effects`
**File:** `/Users/dayna.blackwell/workspace/blackdot/internal/cli/config.go:14–25`
**Tool:** Grep + Read
**Confidence:** High

```go
var (
    configLayerUser    = filepath.Join(os.Getenv("HOME"), ".config", "blackdot", "config.json")
    configLayerMachine = filepath.Join(os.Getenv("HOME"), ".config", "blackdot", "machine.json")
)

func init() {
    if xdg := os.Getenv("XDG_CONFIG_HOME"); xdg != "" {
        configLayerUser = filepath.Join(xdg, "blackdot", "config.json")
        configLayerMachine = filepath.Join(xdg, "blackdot", "machine.json")
    }
}
```

Two issues:

1. **Package-level var initialization reads `HOME` at import time.** If a test sets `HOME` after package import (e.g., `t.Setenv("HOME", tmpDir)`), the global vars are already frozen to the real home directory. Tests that exercise `configGet`, `configSet`, or `configShow` will read/write to the real user config, not the test fixture.

2. **`init()` reads `XDG_CONFIG_HOME` at init time.** Same issue: environment overrides set by tests after package init are invisible.

Note that `internal/config/config.go` already solves this correctly using `DefaultManager()`, which reads the environment lazily at call time (lines 82–100). The `cli/config.go` implementation duplicates the path-resolution logic without the lazy-evaluation fix, making the CLI config commands behave differently from the config package.

**Impact:** Test isolation broken for config command tests. Tests that change `HOME` or `XDG_CONFIG_HOME` after import will silently read/write real paths.

### M-3: `getNestedValue` Version Serialization Produces Incorrect Results for Multi-Digit Versions

**Severity:** Medium
**Check:** `scope_analysis` (logic error)
**File:** `/Users/dayna.blackwell/workspace/blackdot/internal/config/config.go:258`
**Tool:** Read
**Confidence:** High

```go
case "version":
    return string(rune(cfg.Version + '0')), nil
```

This converts an integer version to a string by adding the ASCII code for `'0'` (`48`). For `Version = 3`, it produces `string(rune(51))` = `"3"`, which is correct. For `Version = 10` (hypothetical future version), it produces `string(rune(58))` = `":"`, which is wrong.

The `Config` struct uses `int` for `Version`, not a single digit. If the version ever exceeds 9, `blackdot config get version` will return a nonsensical character. The correct approach is `strconv.Itoa(cfg.Version)` or `fmt.Sprintf("%d", cfg.Version)`.

**Impact:** `blackdot config get version` returns garbage for any version number >= 10.

### M-4: Duplicate Config Path Resolution — `cli/config.go` Bypasses `config.Manager`

**Severity:** Medium
**Check:** `duplicate_semantics`
**File:** `/Users/dayna.blackwell/workspace/blackdot/internal/cli/config.go:256–289` vs `internal/config/config.go:185–232`
**Tool:** Read + Grep
**Confidence:** High

`internal/config/config.go` exports `Manager.GetLayered()` which implements the full 5-layer resolution chain (env → project → machine → user → default). `internal/cli/config.go` re-implements the same chain in `configGet()` using private helpers (`getFromJSONFile`, `findProjectConfig`) that read JSON directly without going through `Manager`.

The two implementations diverge in:
- **Path normalization:** `config.DefaultManager()` applies `filepath.Clean` for XDG paths; `cli/config.go` does not.
- **Error handling:** `config.Manager.loadFile()` distinguishes `IsNotExist` from other IO errors; `getFromJSONFile()` silently returns `""` for all errors.
- **Project config location:** `config.Manager.ProjectConfigPath()` compares after symlink resolution; `cli/config.go`'s `findProjectConfig()` does a plain stat check.

This means `blackdot config get` and `blackdot config show` can produce different results from what `config.Manager.Get` returns when called by the feature registry.

**Impact:** Layer resolution divergence between CLI commands and internal feature state. Users debugging config values with `blackdot config show` may see different results than what features actually use.

### L-1: `BlackdotDir()` Returns Empty String Before First Command Run

**Severity:** Low
**Check:** `scope_analysis`
**File:** `/Users/dayna.blackwell/workspace/blackdot/internal/cli/root.go:26–28, 127–142, 145–147`
**Tool:** Read
**Confidence:** High

`blackdotDir` is a package-level variable initialized to `""`. It is populated by `initConfig()`, which Cobra registers via `cobra.OnInitialize` (line 79). Any code that calls `BlackdotDir()` before the first command execution (e.g., in tests, or if called during `init()`) receives an empty string.

```go
var blackdotDir string  // empty until initConfig() runs

func BlackdotDir() string {
    return blackdotDir  // may be "" if called before Cobra initialization
}
```

`getSessionFile()` in `vault.go` calls `BlackdotDir()` unconditionally and incorporates the result into a path. If `blackdotDir` is empty, the session file path becomes `"vault/.vault-session"` — a relative path that silently places the session file in whatever the process's CWD is.

The issue is documented in the previous report (item 10 in Remaining Work). It has not been addressed.

func runBackupRestore(cmd *cobra.Command, args []string) error {

This function exists solely as a wrapper around `runBackupRestoreImpl`. It is called once from `rollback.go:314` (`runBackupRestore(nil, []string{backupID})`), but `runBackupRestoreImpl` is also directly accessible. The wrapper adds no logic and passes `nil` as the `*cobra.Command` argument.

## Recommended Fix Order

1. **H-2 (sync.go write failures)** — Guard both `os.WriteFile` calls; return errors or at minimum `Warn()` the user. Consider using `config.DefaultManager()` instead of the hardcoded path in `updateSyncTimestamps`.

2. **M-3 (version serialization)** — Replace `string(rune(cfg.Version + '0'))` with `strconv.Itoa(cfg.Version)` to fix multi-digit version handling.

3. **H-1 (checkTerminal dead code)** — Remove `checkTerminal()` from style.go or wire it to `NoColor()` / `color.NoColor` initialization.

4. **M-2 (init side effects in cli/config.go)** — Replace the package-level vars and `init()` with a lazy `getConfigLayers()` function that reads env at call time, matching the pattern in `config.DefaultManager()`.

5. **M-4 (dual config resolution)** — Replace `configGet` and `configShow` in cli/config.go with calls to `config.DefaultManager().GetLayered()` to eliminate the divergence.

6. **M-5 (dead Engine type)** — Add a `//Deprecated:` godoc comment to `engine.go`, or delete it if no callers are planned. Add test coverage for `RaymondEngine` to fill the gap left by the superseded regex engine.

7. **M-1 (color export cleanup)** — Delete the 19 dead `Clr*` exports and 7 other dead utility exports. Standardize callers on the legacy names (Red/Green/Yellow etc.) which are the actual in-use set, and document them as the canonical API.

8. **L-2 (RaymondEngine test coverage)** — Add `raymond_engine_test.go` tests covering `Render`, `SetVar`, `LoadVariablesFile`, and error cases.
